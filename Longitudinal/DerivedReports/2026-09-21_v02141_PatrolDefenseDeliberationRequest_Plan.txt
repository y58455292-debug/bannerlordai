BannerlordAI v0.2.10.41 — Read-only PatrolDefense deliberation request packet shadow

Question
Can PatrolDefense construct the exact bounded input packet a future expensive reasoner would consume, only when v0.2.10.40 says reconsideration is warranted, without invoking a model/planner or changing behavior?

Prior art
- SkyrimNet GamePlugin: actor-local knowledge, eligibility caching, event-driven/off-screen reasoning.
- SeverActions: high-level intent is separated from registered/legal deterministic execution.
- Inworld ecosystem: structured cognition metadata is separated from downstream tools/actions.
- BannerlordAI v0.2.10.40 now provides the factual reconsideration boundary.

Smallest implementation
- Runner-only; reuse accepted v0.2.10.38 ClanAI and v0.2.10.40 actorKnown/reconsideration inputs.
- Add pure PatrolDefenseDeliberationRequestBuilder.
- Input:
  exact actorKnownContext JSON,
  exact reconsiderationEvidence JSON,
  baseline decision facts already produced by PatrolDefenseShadow:
    wouldInterrupt, safeToIntervene, reason, candidateAction, resumeAction.
- If reconsiderationCandidate=false, return null.
- If true, emit BannerlordAI.PatrolDefenseDeliberationRequest.v1:
  mode=observe,
  source=PatrolDefenseShadow.v02141.deliberation_request,
  actorKnownContext exact,
  reconsiderationEvidence exact,
  baselineDecision exact,
  deterministic requestFingerprint over stable current component fingerprints + baseline decision fields,
  requestEligible=true,
  llmInvoked=false,
  plannerInvoked=false,
  interpretationApplied=false,
  behaviorMutation=false,
  intentMutation=false,
  scoreMutation=false,
  nativeMovementCalls=0.
- Nest as deliberationRequest in the shadow receipt after reconsideration evidence.
- No network/model/tool call. No policy output. No action ownership.

Acceptance
A. Runner compiles; ClanAI unchanged.
B. Fixtures:
   eligible reconsideration -> exact request;
   ineligible reconsideration -> null;
   same stable inputs -> same requestFingerprint;
   changed actor-known/reconsideration stable fingerprints -> fingerprint changes;
   baseline decision field change -> fingerprint changes;
   request preserves exact nested actorKnown/reconsideration JSON;
   no LLM/planner/Apply/score/memory write surfaces.
C. Static ordering: baseline Evaluate -> actorKnownContext -> reconsiderationEvidence -> deliberationRequest.
D. Live: one natural first-observation Manan shadow (already naturally eligible by v0.2.10.40 semantics) emits deliberationRequest with exact nested contexts and exact baseline decision snapshot, requestEligible=true, llmInvoked=false, plannerInvoked=false, zero decision/Apply authority.
E. EXIT_NOSAVE integrity cleanup.

Scope
This is only the deterministic input envelope for future cognition. It does not define prompts, semantic judgments, utility weights, model routing, or action selection.
