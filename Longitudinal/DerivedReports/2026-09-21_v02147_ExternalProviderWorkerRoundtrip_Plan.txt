BannerlordAI v0.2.10.47 - External provider-worker roundtrip integration shadow

Question
Can an external/off-game-thread worker consume the exact v0.2.10.46 outbox job, produce a strict advisory response, and return it through the accepted v0.2.10.44 admission transport without any in-game provider invocation or gameplay authority?

Why this gate
- v0.2.10.46 proves game-thread dispatch/outbox handoff.
- v0.2.10.44 proves exact runtime response admission/consume-on-success.
- Portal Agent / DeepAstra / DeepSeek Harness support serialized controller -> worker -> review patterns.
The missing proof is end-to-end handoff across the process boundary using the existing primitives.

Implementation
- Reuse v0.2.10.46 ClanAI/runner unchanged.
- Validator acts as deterministic external worker; this is test harness, not product logic.
- Live flow:
  1. Natural first unseen Manan request is ENQUEUED to outbox.
  2. External validator reads the exact outbox job after it appears.
  3. Worker validates job schema/state/fingerprint/request.
  4. Worker constructs strict KEEP_BASELINE advisory JSON using only the exact job requestFingerprint.
  5. Worker submits via existing PATROL_DEFENSE_ADVISORY_ADMIT <fingerprint> <base64Json>.
  6. Existing v0.2.44 runtime gate/strict admission must admit=true and consume the pending request.
  7. Immediate identical worker replay must reject NO_PENDING_ROUTE_REQUEST.
- Provider invocation jsonl must remain empty because no in-game provider implementation is used.
- No network/model call; worker is deterministic local Python validation code.

Acceptance
A. No feature binary changes from v0.2.10.46.
B. Static hashes exactly equal accepted v0.2.10.46 candidate hashes.
C. Live outbox job exact and PENDING.
D. External worker advisory exact fingerprint; runtime admission admitted=true/KEEP_BASELINE/executionAuthorized=false.
E. Replay rejected NO_PENDING_ROUTE_REQUEST.
F. Provider invocation stream remains empty; model/network flags false; no Apply side effects.
G. EXIT_NOSAVE integrity cleanup.

Scope
This proves external worker transport composition only. It still does not call a real model or select a provider/vendor.
