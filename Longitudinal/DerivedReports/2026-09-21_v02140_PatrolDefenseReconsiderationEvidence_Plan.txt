BannerlordAI v0.2.10.40 — Read-only PatrolDefense factual reconsideration evidence shadow

Question
Can PatrolDefense detect when actor-known factual context materially changes so future expensive reasoning can be event-driven, without assigning semantic danger/utility scores or changing behavior?

Prior art
- Schut & Wooldridge BDI intention-reconsideration work: commitment depends on when an agent reconsiders; reconsideration policy can be dynamic instead of constant.
- Unreal Behavior Tree/Blackboard: actor state is updated at defined service boundaries and behavior reads the updated state.
- SkyrimNet/event-driven cognition prior art: expensive cognition should trigger from meaningful events/context changes rather than every tick.
- Accepted BannerlordAI rule: commitment/hysteresis should be calibrated from runtime change/switch evidence, not invented constants.

Smallest implementation
- Runner-only, session-local helper over accepted v0.2.10.39 actorKnownContext inputs.
- Build a stable factual context signature from:
  actorId + branchId + settlementId + banditId,
  currentThreat five-value snapshot,
  persistent-memory stable identity/provenance when present,
  recent-outcome stable identity (FOUND/NONE + eventKey when FOUND) when present.
- Explicitly EXCLUDE volatile clocks/ages such as currentCampaignHours, memoryAgeHours, outcomeAgeHours so time passage alone does not create reconsideration churn.
- Keep one previous signature for the active PatrolDefense intent.
- Emit BannerlordAI.PatrolDefenseReconsiderationEvidence.v1:
  firstObservation,
  factualContextChanged,
  changedComponents[] from {identity,currentThreat,persistentMemory,recentOutcome},
  previous/current component fingerprints,
  reconsiderationCandidate = firstObservation || factualContextChanged,
  interpretationApplied=false; behavior/intent/score mutation=false; nativeMovementCalls=0.
- This is only evidence that a deliberation boundary exists; it does NOT invoke an LLM/planner, add utility, or change candidateAction/Apply.

Acceptance
A. Runner compiles; no ClanAI change.
B. Pure fixtures:
   first observation -> candidate true;
   exact repeat -> false;
   recent outcome age/current time changes alone -> false;
   threat scalar change -> currentThreat component change;
   persistent episode/provenance change -> persistentMemory change;
   recent eventKey/result change -> recentOutcome change;
   identity change -> identity change;
   null<->present transitions trigger the corresponding component.
C. Static ordering: baseline Evaluate + actorKnownContext construction occurs before reconsideration evidence.
D. One bounded live Manan shadow emits first-observation reconsideration evidence with exact actor-known identity and zero decision/Apply authority. Repeat/changed families are fixture-proven; do not force natural world changes merely for this gate.
E. Full EXIT_NOSAVE integrity cleanup.

Scope
No freshness threshold, utility score, semantic danger label, LLM call, commitment bonus, or action change. This gate only establishes an event-driven deliberation boundary.
