BannerlordAI v0.2.10.50 - Exclusive provider job claim / attempt identity shadow

Question
Can an external worker claim exactly one pending dispatch job before expensive cognition so two workers cannot both spend compute on the same request, without inventing a lease timeout or adding a real model?

Prior art
- DeepAstra: bounded task -> worker -> review with isolated runs and explicit worker/task state.
- DeepSeek Harness: bounded worker delegation with persistent sessions and explicit worker ownership.
- Portal Agent: serialized controller/tool work queue.
- v0.2.10.46-.49 provide exact jobs, result provenance and terminal completion lifecycle.

Smallest implementation
- Runner-only; ClanAI unchanged.
- Extend PatrolDefenseProviderDispatchJob with:
  providerId
  attemptId
  claimedUtcTicks
  state=PENDING or CLAIMED.
- Add exact Claim(requestFingerprint, providerId, attemptId, claimedUtcTicks):
  invalid/missing fields -> INVALID_CLAIM;
  no job -> DISPATCH_JOB_NOT_FOUND;
  PENDING -> CLAIMED, claimApplied=true;
  already CLAIMED by same providerId+attemptId -> idempotent SAME_ATTEMPT_ALREADY_CLAIMED, no mutation;
  already CLAIMED by different provider/attempt -> ALREADY_CLAIMED, reject.
- No TTL/timeout/automatic steal in this milestone.
- Existing completion/removal still works on CLAIMED jobs.
- Add command:
  PATROL_DEFENSE_PROVIDER_JOB_CLAIM <requestFingerprint> <providerId> <attemptId>
- Dedicated receipt:
  BannerlordAI.PatrolDefenseProviderJobClaim.v1
  requestFingerprint, providerId, attemptId,
  claimApplied, idempotent, reason,
  stateBefore, stateAfter,
  queueCount,
  claimedUtcTicks,
  externalNetworkUsed=false,
  modelInvoked=false,
  executionAuthorized=false,
  zero gameplay authority.
- Dedicated claim jsonl evidence stream.
- Outbox row stays immutable PENDING evidence; claim receipt is the authoritative session-local ownership transition.

Acceptance
A. Runner compiles; ClanAI unchanged.
B. Fixtures:
   first exact claim PENDING->CLAIMED;
   same provider+attempt replay idempotent;
   different provider rejected ALREADY_CLAIMED;
   same provider different attempt rejected;
   invalid fingerprint/provider/attempt rejected;
   missing job rejected;
   completion SUCCESS removes CLAIMED job;
   TRANSIENT_FAILURE retains CLAIMED job in this milestone;
   reset clears claimed jobs;
   sequence monotonic;
   zero-authority receipt.
C. Static: no timeout constant, no network/OpenAI/provider SDK, no Apply/score/memory write.
D. Live:
   natural request enqueues one job;
   claim exact job as providerId=deterministic_external_worker, attemptId=attempt-1;
   claimApplied=true, PENDING->CLAIMED;
   identical claim replay is idempotent;
   competing claim attempt-2 rejected ALREADY_CLAIMED;
   no provider/model invocation;
   no Apply side effects.
E. EXIT_NOSAVE integrity cleanup.

Scope
This establishes exclusive worker ownership only. Provider result envelopes are not yet required to prove they match the active claim; that binding is the next gate.
