BANNERLORDAI — AUTONOMOUS CAMPAIGN OPERATOR DESIGN
Date: 2026-09-18 Pacific

Purpose:
Allow a durable agent-controlled player proxy to run long Bannerlord campaign field tests from cloned dynasty saves without requiring the user to manually play every run.

Evidence/prior-art basis:
- Google DeepMind SIMA/SIMA 2 demonstrate agents can act in game worlds from goals and accumulate experience useful for later improvement.
- AAA game-testing research shows scripted/learned agents can expand automated playtest coverage.
- BannerlordAI already has a deterministic TestRunner command channel, blocker detection, no-save exit, telemetry, and native campaign movement boundaries discovered by Inspector.

Architecture:
WORLD SNAPSHOT -> OPERATOR POLICY/REASONER -> ALLOWED HIGH-LEVEL ACTION -> VALIDATOR -> BANNERLORD NATIVE EXECUTION -> OUTCOME -> TELEMETRY/MEMORY.
Do not make screen pixels or mouse timing the authoritative control surface when native campaign APIs are available.

Initial allowed strategic actions:
- hold/wait
- travel to point or settlement
- engage/avoid/escort a party where eligible
- patrol/defend settlement
- raid/besiege only when doctrine and eligibility allow
- adjust time control
- pause on unknown blocker or unsafe state
Scope stages:
A. Autonomous Observer: park/safely constrain player and let world evolve while collecting longitudinal AI data.
B. Strategic Player Proxy: operator chooses campaign goals/actions; native Bannerlord executes movement/pathfinding and normal AI systems.
C. Interaction Handlers: deterministic handlers for common menus, inquiries, diplomacy/kingdom votes, settlement entry, battle-resolution choices.
D. Optional embodied UI control later if a trustworthy screen/keyboard/mouse control surface becomes available.

First-version battle rule:
Do not attempt human-style tactical combat. Use safe native/auto-resolve handling when validated, otherwise pause and mark the blocker. Tactical-control automation is a separate research problem.

Experimental use with dynasty saves:
- Hash originals and never write to them.
- Clone each anchor into Vanilla-control and ClanAI-treatment branches.
- Run matched campaign-time horizons under the same operator doctrine.
- Record operator decisions separately from NPC AI decisions.
- Compare trajectories, not frame-exact replay, because RNG and world-event divergence will grow over time.
- Use multiple historical anchors to test different political/geographic eras.

Success criteria:
- unattended bounded run completes without corrupting original saves
- every operator action has state snapshot, reason, eligibility result, and outcome
- unknown situations fail closed/pause
- deterministic/native executor remains separate from policy reasoning
- long-run telemetry supports Vanilla-vs-ClanAI comparisons
- user can watch the visible campaign evolve while the operator runs

Important limitation:
Current Remote Desktop Commander connection exposes filesystem/terminal control, not direct GUI mouse/keyboard control. Therefore first implementation should be Bannerlord-side strategic control, not simulated human clicking.
