BannerlordAI v0.2.10.46 - Non-blocking serialized cognition-provider dispatch/outbox shadow

Question
Can route-eligible deliberation requests be handed off from the game thread into a bounded serialized provider-work queue without invoking a model, blocking gameplay, duplicating jobs, or bypassing exact request/admission correlation?

Prior art
- Portal Agent: persistent controller + serialized tool queue; separate orchestration from tool execution.
- DeepAstra / DeepSeek Harness: main-agent -> bounded task -> worker -> review with isolated task state and explicit completion.
- SkyrimNet: event-driven/off-screen cognition should not run every tick.
- v0.2.10.41-.45 already provide stable request fingerprints, route eligibility, strict response admission and provider abstraction.

Smallest implementation
- Runner-only; ClanAI unchanged.
- Add PatrolDefenseProviderDispatchQueue, session-local and bounded to 32 jobs.
- Job identity = exact requestFingerprint.
- Each job stores:
  requestFingerprint,
  exact deliberationRequest JSON,
  sequence number,
  state=PENDING,
  enqueuedUtcTicks.
- Enqueue only when v0.2.10.42 routeEligible=true.
- Exact duplicate fingerprint while pending/seen in current patrol intent returns duplicate=false enqueue suppression; do not create a second job.
- Deterministic oldest eviction only for completed/removed jobs; never evict an active pending job to admit more work. If capacity full of pending jobs, reject enqueue with QUEUE_FULL.
- Reset queue on campaign/patrol arm/clear boundaries.
- Emit evidence receipt BannerlordAI.PatrolDefenseProviderDispatch.v1:
  requestFingerprint,
  enqueued,
  reason in {ENQUEUED,DUPLICATE_REQUEST,QUEUE_FULL,INVALID_REQUEST},
  queueCount,
  capacity=32,
  providerInvoked=false,
  externalNetworkUsed=false,
  modelInvoked=false,
  executionAuthorized=false,
  zero gameplay authority.
- Append receipt after route eligibility in the shadow evidence.
- Also append exact enqueued job to a dedicated local jsonl outbox evidence stream.
- No worker consumes jobs yet. No provider/network/model call.

Acceptance
A. Runner compiles; ClanAI unchanged.
B. Fixtures:
   first valid request enqueues one job;
   duplicate same fingerprint does not add second job;
   changed fingerprint enqueues;
   invalid/null request rejected;
   capacity full of pending jobs returns QUEUE_FULL without evicting pending jobs;
   reset clears queue;
   exact request JSON preserved;
   sequence increments monotonically;
   receipt zero authority.
C. Static ordering:
   baseline -> actorKnown -> reconsideration -> deliberationRequest -> routeEligibility -> dispatch.
D. Live:
   one natural first unseen Manan request emits ENQUEUED dispatch with same exact fingerprint and queueCount=1;
   local outbox row contains exact deliberationRequest JSON;
   no provider/model/network invocation occurs during this gate;
   no Apply side effects.
E. EXIT_NOSAVE integrity cleanup.

Scope
This milestone only proves non-blocking serialized handoff from gameplay reasoning to future provider work. No worker/model consumes the queue yet.
