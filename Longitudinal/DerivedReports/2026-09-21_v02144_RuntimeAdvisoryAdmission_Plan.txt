BannerlordAI v0.2.10.44 - Exact live deliberation advisory admission transport shadow

Question
Can an advisory response be submitted at runtime only against the exact current route-eligible deliberation request fingerprint, admitted through v0.2.10.43, and still remain disconnected from gameplay?

Why this gate
- v0.2.10.41 creates deterministic requests.
- v0.2.10.42 makes first unseen requests route-eligible and suppresses duplicates.
- v0.2.10.43 validates response schema offline.
The missing boundary is exact live request-response correlation before any real model transport is added.

Smallest implementation
- Runner-only; ClanAI unchanged.
- Track one pending route-eligible request fingerprint for the active PatrolDefense intent.
- When v0.2.10.42 emits routeEligible=true, store that exact fingerprint as pending.
- Add pure PatrolDefenseAdvisoryRuntimeGate:
  no pending request -> reject NO_PENDING_ROUTE_REQUEST;
  submitted fingerprint mismatch -> reject PENDING_REQUEST_FINGERPRINT_MISMATCH;
  exact pending -> run v0.2.10.43 strict admission validator.
- On admitted=true, consume/clear the pending request so replay cannot be admitted twice.
- Rejected malformed/schema responses do not consume the pending request, allowing corrected retry.
- Reset pending fingerprint on campaign instance / patrol arm / patrol clear.
- TestRunner command:
  PATROL_DEFENSE_ADVISORY_ADMIT <requestFingerprint> <base64Utf8Json>
- Command decodes JSON, applies exact pending-request gate, appends a read-only admission receipt to a dedicated jsonl evidence stream.
- No Apply/action/score/movement/memory write.
- No actual model/network call.

Acceptance
A. Runner compiles; ClanAI unchanged.
B. Pure fixtures:
   no pending rejected;
   mismatch rejected and pending retained;
   malformed exact-pending rejected and pending retained;
   valid exact-pending advisory admitted and pending consumed;
   replay after consume rejected;
   arm/reset makes state empty;
   all three allowed dispositions can pass through exact pending gate;
   zero execution authority.
C. Static: runtime command exists, base64 decode only, no network/model/Apply/score/write.
D. Live:
   natural first unseen Manan request becomes pending;
   harness submits a synthetic valid KEEP_BASELINE advisory bound to its exact requestFingerprint;
   receipt admitted=true, disposition=KEEP_BASELINE, executionAuthorized=false;
   immediate identical replay returns NO_PENDING_ROUTE_REQUEST / admitted=false;
   baseline PatrolDefense decision remains unchanged; no Apply side effects.
E. EXIT_NOSAVE integrity cleanup.

Scope
This proves request-response correlation and admission transport only. It still does not call an LLM, decide that KEEP_BASELINE is correct, or influence gameplay.
