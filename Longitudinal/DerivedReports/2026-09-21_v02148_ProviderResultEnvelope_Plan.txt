BannerlordAI v0.2.10.48 - External provider result envelope/provenance admission shadow

Question
Can BannerlordAI accept an external worker result only when provider/attempt provenance, request fingerprint, status, and advisory payload form a valid exact result envelope, while failures remain fail-closed and the advisory still passes strict v0.2.10.43-.44 admission?

Why this gate
- v0.2.10.46-.47 prove serialized external handoff and response return.
- Before a real provider/model is introduced, results need explicit provenance and failure semantics so transport/provider errors cannot masquerade as valid cognition output.

Smallest implementation
- Runner-only; ClanAI unchanged.
- Strict flat result envelope schema:
  BannerlordAI.PatrolDefenseProviderResult.v1
  required fields:
    schema
    providerId
    attemptId
    requestFingerprint
    status
    advisoryBase64
- Allowed status enum:
  SUCCESS
  TRANSIENT_FAILURE
  PERMANENT_FAILURE
- SUCCESS requires nonempty advisoryBase64.
- Failure statuses must not be admitted and may omit/empty advisoryBase64.
- Exact pending request fingerprint still required.
- providerId and attemptId are required nonempty provenance strings.
- Add PatrolDefenseProviderResultAdmission:
  malformed/missing/unknown fields reject;
  unknown status reject;
  request mismatch reject;
  SUCCESS decodes advisory and sends through existing PatrolDefenseAdvisoryRuntimeGate strict admission;
  provider failure status returns admitted=false with PROVIDER_TRANSIENT_FAILURE or PROVIDER_PERMANENT_FAILURE and does not consume pending request;
  malformed/invalid advisory does not consume pending request;
  successful strict admission consumes pending request.
- TestRunner command:
  PATROL_DEFENSE_PROVIDER_RESULT_ADMIT <base64Utf8EnvelopeJson>
- Receipt schema:
  BannerlordAI.PatrolDefenseProviderResultAdmission.v1
  providerId, attemptId, requestFingerprint, status,
  providerResultAccepted,
  advisoryAdmission,
  retryable,
  executionAuthorized=false,
  modelInvoked=false at this milestone,
  zero gameplay authority.
- Dedicated jsonl receipt stream.

Acceptance
A. Runner compiles; ClanAI unchanged.
B. Fixtures:
   SUCCESS exact envelope + valid KEEP_BASELINE advisory admitted;
   wrong fingerprint rejected and pending retained;
   missing providerId/attemptId/status rejected;
   unknown/extra fields rejected;
   unknown status rejected;
   TRANSIENT_FAILURE rejected retryable=true and pending retained;
   PERMANENT_FAILURE rejected retryable=false and pending retained;
   malformed base64/advisory rejected and pending retained;
   SUCCESS consumes pending;
   replay after success rejected NO_PENDING_ROUTE_REQUEST;
   strict action-bearing advisory still rejected by v0.2.43 admission.
C. Static: no network/OpenAI/provider SDK, no Apply/score/memory write.
D. Live:
   natural outbox request;
   external validator submits synthetic SUCCESS result envelope with providerId=deterministic_external_worker, attemptId=attempt-1, exact fingerprint, valid KEEP_BASELINE advisory;
   result admission accepted=true, nested advisory admitted=true, executionAuthorized=false;
   replay rejected because pending consumed;
   provider invocation stream empty.
E. EXIT_NOSAVE integrity cleanup.

Scope
This defines worker result provenance/failure semantics only. Still no real model/network call.
