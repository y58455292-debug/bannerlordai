BANNERLORDAI ROLLING CONTEXT / SELF-COMPACTING INDEX METHOD
Saved: 2026-09-18

Goal:
Prevent project context, evidence indexes, and reasoning inputs from growing indefinitely.
Keep active reasoning small and fast without losing traceability.

THREE-TIER INDEX

1. HOT INDEX
Only information needed for the next decision:
- current deployed build + hashes
- current campaign save/checkpoint
- current test hypothesis
- current telemetry session
- unresolved questions
- latest confirmed world state
- immediate next action

2. WARM INDEX
Verified findings that still affect current architecture:
- proven causal mechanisms
- validated thresholds
- active design doctrine
- recent milestone summaries
- known limitations
- current architecture decisions

3. COLD ARCHIVE
Everything else remains available but is not injected into normal reasoning:
- raw telemetry
- old session logs
- screenshots/video
- Behavior Delta CSVs
- superseded builds
- historical source
- prior save checkpoints
- detailed reports

END-OF-TEST COMPACTION
At every completed test:
1. Freeze raw evidence.
2. Save campaign checkpoint.
3. Produce structured session summary.
4. Deduplicate repeated findings.
5. Promote new verified conclusions into WARM.
6. Keep only next-test essentials in HOT.
7. Mark superseded hypotheses/results as retired.
8. Preserve evidence IDs/paths back to raw source.
9. Do not carry old raw detail forward unless explicitly needed.

RETRIEVAL RULE
Reason from HOT first.
Consult WARM only when necessary.
Retrieve COLD evidence only for verification, contradiction resolution, or deep investigation.

COMPRESSION RULE
raw -> short-window -> campaign-day -> session -> build -> cross-build conclusion

IMPORTANT
- Compression never deletes source truth.
- Superseded conclusions must remain discoverable but not active.
- Unknown stays UNKNOWN.
- Do not repeatedly re-read large historical files when a verified summary exists.
- If a current result contradicts a summary, return to raw evidence and revise the summary.
- Keep evidence links/hashes so compact summaries are auditable.

EXPECTED BENEFIT
Less repeated context, cleaner decisions, fewer old assumptions leaking into current work, faster retrieval, and lower reasoning clutter over long-running BannerlordAI development.
