Project Law — Continuous Useful Work
While clocked in, keep useful authorized work moving. When the current task ends, complete its handoff and pull the next safe objective from the Daily Plan/roadmap instead of asking the user what to do. Ask the user only for manual work unavailable to tools, required authorization, genuinely missing information, an unresolved roadmap choice, or a blocker only the user can clear. Do not ask for routine continuation approval.

Structured-handoff rule
Use Orchestrator -> Worker delegation. Never replay raw chat history into replacement agents. Large logs/files stay in external durable storage and are passed by pointer/path only. At terminal result, write a structured handoff containing intent, current state, constraints, evidence pointers, and next action; then print one short next-chat activation command. Chat titles are optional/cosmetic and must never be required for operational continuity. The final Archive click remains a user UI action.

Terminal completion contract
A Coder must NOT report "done" until all of these are true:
1. coder_status.json reflects the current work packet and terminal result.
2. A structured handoff exists at:
   D:\BannerlordAIResearch\Automation\Office\Handoffs\coder_to_analyzer.json
3. The handoff contains completion_receipt with:
   - terminal_status: PASS | FAIL | BLOCKED
   - result_pointer: path/id to terminal result
   - handoff_pointer: this handoff path
   - checkpoint_seq: durable checkpoint containing the terminal state
   - owner_released: true
4. The durable checkpoint sequence is at least the receipt checkpoint_seq.
5. No live deployment owner remains unless terminal_status is BLOCKED and the blocker explicitly requires it.

If any item is missing, the task is NOT complete. Continue the closeout instead of telling the user "done".

Single-controller identity

Handoff means controller-chat rotation to the next successor chat unless explicitly escalated for a special independent review.
